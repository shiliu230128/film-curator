# 推荐策略

本文件是推荐候选、过滤、排序、解释和反馈学习的唯一规则来源。周/月/季计划的容量与排布见 `planning.md`。

## 推荐不是一次排序

完整流程是：确定范围 → 收集当下约束 → 构造候选池 → 硬过滤 → 可解释评分 → 组合检查 → 输出与记录。硬约束优先于任何偏好分数，候选不足时减少推荐数量，不用低质量作品凑满 3 部。

## 候选池与范围

- “从我的影单选”：只使用统一记录库中 `want` 或 `watching` 的记录。
- 普通推荐默认使用动态范围：先从库内 `want/watching` 中取满足硬约束的候选；若候选数量不足，或库内没有任何符合项，再从库外候选补足。库内影单是可用线索，不是用户真实喜好的完整代表，不能因为某片被加入就推断用户喜欢它。
- 用户说“只从我的影单选”时严格只用库内；用户说“推荐没看过的/允许探索”时可直接使用库外；库外候选只有被用户采纳后才写入记录库，并保留 `source_tier=external`。
- 用户随口提到“可能想看”的内容、Skill 检索到的候选和外部 JSON 候选，默认先进 `candidate_pool.json` 或作为本次临时候选使用，不直接进入 `watchlist.json`。这能避免把“随手一提”误当成正式待看和偏好证据。
- 主题策展：围绕用户指定的导演、地区、流派、时代或母题建池，不用个人偏好把主题稀释掉。
- 重看请求：只从已看历史中选，并提供与上次不同的观察角度。

片名、年份、导演、时长和豆瓣评分属于事实字段。无论库内还是库外，无法确认时都留空或标注未知，不能凭感觉补数值。豆瓣评分是参考信号，不参与个人偏好学习。

## 硬过滤

默认排除以下候选：

- 命中明确 `avoided_genres` 或用户本次声明的禁区；
- 状态为 `dropped`，除非用户主动要求重新考虑；
- 已看作品，除非本次是重看；
- 超出明确时长上限；
- 近 14 天已经看过或推荐过；
- 用户指定内容类型、语言、地区或剧透边界时不符合条件。

缺少时长不等于自动符合时长限制。时间要求严格时，应先核实或换成时长已知候选。

语言默认是软权重，不是硬过滤。用户只是“能看外语片”时，外语片仍可进入候选；但用户说“不方便一直盯字幕”或画像里的 `subtitle_mode=subtitle_sensitive` 时，非偏好语言会降低排序。只有用户明确说“这次不要外语片/只看中文”时，语言才作为硬过滤。

## 可解释评分

CLI 当前原始分规则：每命中一个偏好类型 +3；喜欢的导演 +3；喜欢的演员交集 +2；情绪或标签匹配 +1；时长适配 +1；叠加每个类型的 `genre_weights`。底层诊断函数仍会为禁区记 -8、近 14 天出现记 -4，但 `rank` 和 `plan` 会先把这些候选硬过滤掉。原始分只用于同一候选池内部排序，不能展示成推荐概率或平台评分。

执行时还要检查三类证据：

1. 稳定偏好：问卷明确偏好、至少两次同方向评分、反复出现的导演或视听偏好。
2. 当下适配：本次时长、情绪、注意力、独看或共看场景。
3. 风险提示：慢热、沉重、暴力、长片或信息密度等可能不适合当下的点。

推荐理由至少引用一条稳定偏好和一条当下适配。数据不足时直说依据有限，不用“非常适合你”等强结论。

## 四种策略

| 策略 | 何时使用 | 约束 |
|---|---|---|
| `precise_match` | 默认主力；用户想稳妥、时间有限或画像较少 | 同时命中画像和本次情境。 |
| `surprise_bridge` | 用户允许探索，且能指出明确桥接点 | 每批最多 1 部；不能跨越禁区；必须解释桥接点和风险。 |
| `theme_curation` | 用户要主题、导演、流派或成长线 | 主题一致性优先，仍需控制节奏和难度。 |
| `classic_revisit` | 用户明确想重看，或历史记录足以提供新角度 | 不用于伪装候选不足；必须给新的观看视角。 |

没有明确“想探索”时，默认全部精准匹配。画像与行为数据不足 5 条时，不主动使用经典回顾。

## 多个候选如何组织

- 即时推荐默认给 2-4 部，按“首选 + 方向不同的备选”组织，不做没有取舍的长名单。首选是当前综合最优解；备选根据用户状态、长期偏好、观看目标和风险差异形成，不固定套用“轻松/探索”标签。
- 每个候选说明它在本次候选组中的角色，例如“更贴近你最近反复提到的家庭关系”“更符合今晚的注意力”“更接近你想完成的作者电影主题”。角色由证据和情境决定。
- 用户明确只要一部时只给一部；用户想比较时，列出 2-4 部并给出时长、情绪承载、主题、陌生度和观看目标的差异，最后仍指出推荐顺序。
- 候选允许且用户没有限定类型时，2-3 部推荐至少覆盖两种 `content_type`。
- 不连续安排两部同类型且同为高情绪强度的作品。
- 每部输出：片名、年份、导演、类型、时长、豆瓣评分（仅有可靠记录时）、推荐理由、风险提示和策略。

计划的容量、机动位、按周分配和季度阶段只定义在 `planning.md`；本文件只负责为计划提供候选排序和推荐理由。

## 反馈学习与日志

- 推荐输出后记录曝光、策略和情境；用户选择时记录 `accepted`，跳过时记录 `skipped`，看完时记录 `watched`。
- 跳过只降低本次策略或桥接点的信心，不等于讨厌影片类型。
- 弃看必须区分作品问题、时机问题和时长问题。
- 评分 8 分及以上小幅上调相关类型权重，5 分及以下小幅下调，权重限制在 -2 到 2。
- 至少积累 5 条新评分再主动总结偏好变化；至少 20 条真实完成记录后，才建议精炼长期画像标签。
- 推荐事件尽量带 `session_id`、`source_tier` 和阶段（`exposed/accepted/started/completed/skipped/dropped`），使曝光到完成可追踪。用户未回应不能记为跳过。
