# Film Curator

Film Curator 让你在打开视频软件之前就定好今晚看什么，顺手把看过什么、打了几分记进飞书或多维表格，或者 Notion。

它是给 AI 助手装的一套本领。装好之后你直接用中文说话，它记得你的口味、禁区，以及这周还剩几个空档。

影单你在飞书或 Notion 里看、改；口味画像和还没正式加入片单的备选留在你电脑上，给推荐用。

## 它用起来什么样

### 一、不知道想看什么，只知道有多少时间

你说：「今晚有两个小时，想看安静但有余味的」

它先在你已经存下的片单里找，不够或不合适才往外找。超过时间的、你标过不看的题材、最近刚看过的同类都会被排掉。已经看过的片子，除非特别合适，否则不会再推给你。最后给一个明确首选，再加一到三个方向不同的备选。

不方便一直盯字幕时直接说「这次不太方便看字幕」。

### 二、排一段时间的片单

你说：「帮我排一下这个月的观影计划」

按周分配，默认不排满，留几个机动位。它先给草案，你确认了才写进记录，并同步到飞书或 Notion。周、月、季度都能排。

### 三、维护自己的影视库

跟 AI 说就行，例如：「把《海街日记》加入想看」「我看完《燃烧》，9 分」。记录会写进本地工作缓存，再推到你的飞书或 Notion 影单。

看完时它会问「我的评分」。还有个可选的「当时适配度」，只在「片子确实好，但我那天累得看不进去」时才填。

### 四、飞书或 Notion 影单

第一次用时它会问：新建一份飞书表、新建一份 Notion 库，还是用你已经有的链接。

只配了一边，以后就默认用那一边。两边都配了，它会再问一次以后默认用哪边。

你给现成链接时，它按标准字段核对接：缺「本地编号、片名、状态、已删除」会补上，你原来多出来的列会保留。

## 怎么用

### 开始之前你需要准备什么

| 需要什么 | 怎么弄到 |
|---|---|
| 一个支持 skill 的 AI 客户端 | Claude Code、Comate 这类 |
| Python 3 | 让 AI 助手帮你确认；没有就到 python.org 安装 |
| 飞书或 Notion 的连接（二选一即可） | 让 AI 助手检查客户端是否已接好，未接则按其指引授权 |

不需要自己跑命令，不需要本地网页。

### 最快的装法

把项目文件夹下载到本地，然后跟你的 AI 助手说：

```
把这个文件夹装成 skill，装完告诉我怎么用
```

装完重开一次对话，说一句「今晚有两个小时，想看点安静的」。它给你推荐了就是装好了。第一次它可能问你口味，也可以跳过。

第一次维护影单时再说：

```
帮我在飞书建一份影单
```

或把现成链接丢给它：「用这个 Notion 链接当我的影单」。

### 想自己动手装

把整个文件夹复制到客户端存放 skill 的目录里。

| 客户端 | Mac / Linux | Windows |
|---|---|---|
| Claude Code | `~/.claude/skills/` | `C:\Users\你的用户名\.claude\skills\` |
| Comate | `~/.comate/skills/` | `C:\Users\你的用户名\.comate\skills\` |

### 接入飞书或 Notion

日常仍然直接跟 AI 对话。两边都需要先能连上对应服务。

#### 飞书

登录[飞书开放平台](https://open.feishu.cn/) 创建自建应用，开通多维表格读写权限，发布后再把 App ID 和 App Secret 配进客户端的 MCP。配置文件通常是 `~/.claude/mcp.json` 或 `~/.comate/mcp.json`：

```json
{
  "mcpServers": {
    "lark-mcp": {
      "command": "npx",
      "args": ["-y", "@larksuiteoapi/lark-mcp", "mcp"],
      "env": {
        "APP_ID": "填入你的 App ID",
        "APP_SECRET": "填入你的 App Secret"
      }
    }
  }
}
```

国际版 Lark 在 `env` 里再加 `"LARK_DOMAIN": "https://open.larksuite.com"`。

#### Notion

到 [Notion 集成页](https://www.notion.so/my-integrations) 新建 Integration，复制以 `ntn_` 开头的密钥。打开要放影单的页面，右上角 Connections 里授权这个 Integration。

```json
{
  "mcpServers": {
    "notion": {
      "command": "npx",
      "args": ["-y", "@notionhq/notion-mcp-server"],
      "env": {
        "NOTION_TOKEN": "填入你的 Internal Integration Secret"
      }
    }
  }
}
```

改完配置要重启一次 AI 客户端。密钥不要发给别人。

| 你说什么 | AI 做什么 |
|---|---|
| 「帮我在飞书建一份影单」 | 按标准模板建「影单」和「观影历史」，把现有记录推上去，给你链接 |
| 「用这个链接当我的影单」 | 绑定、核对字段、缺的必填列补上 |
| 「把刚改的同步上去」 | 把本地最新变化推到云端 |
| 「从飞书/Notion 同步回来」 | 把你在云端改过的拉回 |
| 想删一条 | 在飞书/Notion 勾上「已删除」，下次同步时本地也会去掉 |

---

### 出问题了怎么办

| 你看到 | 意思是 | 怎么解决 |
|---|---|---|
| 电脑上还没装 Python | 让 AI 助手帮你确认并指引安装 | Windows 安装时勾上 Add Python to PATH |
| 找不到某部片子的记录 | 片名对不上或还没加入 | 让 AI 先在片单里搜一遍 |
| 评分超出范围 | 只认 0 到 10 | 改成这个范围再说一次 |
| 状态词它不认识 | 只认想看、在看、看过、弃看 | 让 AI 改一次 |
| 飞书/Notion 连不上 | 客户端还没配好对应连接 | 让 AI 按上面的接入步骤检查 |

### 它不能做什么

- 不知道在哪能看。不查片源平台。
- 不是多人共用账号。云端同步的是你的影单和观影历史。
- 不保证所有年份、导演、评分、海报都能补齐。查不到就留空。
- 不做本地网页，也不从 Excel/CSV 文件整表搬家；进出都走对话和飞书/Notion。

装在能联网的客户端里，片单不够用时可以从外面给你新建议。装在不联网的环境里，它只吃你已经记下的片单和口味。

## 项目里都有什么

**你的口味和备选**在 `data` 文件夹。正式片单以飞书或 Notion 为准，本地那份是工作缓存。

| 文件 | 装的是 |
|---|---|
| `watchlist.json` | 正式片单的本地缓存 |
| `candidate_pool.json` | 还没正式加入片单的候选 |
| `history.json` | 观影历史的本地缓存 |
| `user_profile.json` | 口味画像 |
| `preference_evidence.json` | 每条偏好结论的依据 |
| `recommend_log.json` | 推荐记录，避免老推同一部 |
| `config.json` | 设置，以及飞书/Notion 绑在哪 |

只有你明确说「加入待看」「采用这部」，候选才会写进正式片单。

**跑起来靠的东西**是 `scripts/`。**想调整它的行为**就改 `SKILL.md` 和 `references/`。
